## What this unlocks — the reason the work happened

Nothing here has been built. This is the menu.

- **Shot placement in 3D.** `GoalmouthY`/`GoalmouthZ` say where each shot
  crossed the line, including height. Every shot chart you have shows where a
  shot came FROM and nothing about where it WENT.
- **Keeper positioning.** `GKx`/`GKy` at the moment of the shot, with
  `PlyrsBtwn` and `Pressure` for context.
- **Team press maps.** `PressureReceived` on 3.1M events — passes, take-ons,
  clearances. Not shots-only. (Presser attribution still does NOT exist;
  `remoteEventsPressureCreated` is empty.)
- **Line-breaking passes.** `LinesBroken` 1-4, plus `LastLineBroken`.
- **Game-state splits on everything.** `MatchState` is on 100% of events, so
  any existing chart can be cut by ahead/behind/tied.
- **Set pieces.** `CornerType` and `ShotPatternOfPlay`.
- **Momentum.** `secondsUntilNextGoal`.

`memory/project_chart_roadmap.md` holds the user's own outline of wanted
charts. **Invoke the `/chart-critique` skill** for anything new.

## The xG question, so it is not lost

`[xG|EVENT]` returns the catalogue's DISPLAY FORMAT, so stored `xG` has **100
distinct values**, 0.01 to 1.00. `event.expectedGoals` is a full float.

And TruMedia's own team xG is `sum(reboundAdjustedExpectedGoals)`, not the
unadjusted sum we use — 1.75% over a season, but **up to 0.70 on a single
rebound goal**, which is a visible step in the wrong place on a match xG race.

Both columns are now stored. Nothing has changed behaviour. **Do not change it
silently** — it is a definitional choice, deferred deliberately.

## Traps that cost time today

**Three gates, and missing one is SILENT.** A column reaches the database only
if it is in `EVENT_LOG_SELECT`, `EVENTS_MD_COLS` **and** the schema.
`EVENTS_MD_COLS` is an allowlist applied BEFORE `_align_to_table`, which then
NULL-fills. The first attempt wrote 1,581 rows with all 52 columns NULL and
reported **"INGEST OK"**. All three now derive from one list;
`test_expanded_columns.py` asserts it.

**An empty practice file proves almost nothing.** It only exercises "insert
into nothing". `test_backfill_overwrite.py` seeds from the local
`event_db/soccer.duckdb` and tests what matters — ALTER on a populated table,
replacement without duplication, DELETE scoped to gameId.

**A work list is only true of the target and seasons it was built against.**
It is cached in session state and used to outlive both.

**The user found four bugs today.** The stale work list, the auto-selected
COMPLETE state, and two wrong claims of mine — that we already had TimeStamp,
and a fabricated warning about orphan seasons appearing in the picker. The
common thread on my side: reporting a derived conclusion before validating
the thing underneath it.
